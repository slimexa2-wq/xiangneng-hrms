# Codex任务：在现有祥能人员与招聘信息管理系统中新增“祥能AI业务助手”

你正在维护一个已经存在的“祥能人员与招聘信息管理系统”。本次任务是在现有系统中新增真正可用、权限受控、数据准确、适合AI大赛演示的AI业务助手。

不得重新搭建独立假系统，不得只制作聊天界面，不得用静态数据冒充查询，不得让模型直接修改数据库。

## 一、唯一依据
先完整阅读本目录：`README.md`、`SKILL.md`、`manifest.json`、`config/`、`router/`、`skills/`、`schemas/`、`prompts/`、`tests/`、`docs/`。这些文件是业务、权限、安全和验收依据。

## 二、开始前只审查，不改业务代码
先输出：前后端技术栈、数据库/ORM、登录会话、角色和数据权限、人员/项目/岗位/供应商实体、人员状态、入职和离职现有页面与服务、在职/入职/离职/招聘缺口统计、可复用组件、测试构建命令、演示与正式环境隔离情况。

然后用真实路径填写 `docs/codex-mapping-guide.md`。未完成映射不得开发写操作。若系统只有前端静态数据，必须明确说明并先建设最小正式业务服务层，不得修改前端数组冒充联动。

## 三、固定功能范围
仅实现：项目人员数据查询、人员信息查询、招聘进度查询、单人入职、单人离职。不得增加工资、结算、批量操作、删除、自由SQL或其他未确认能力。

## 四、架构
```text
现有前端AI助手
→ AI后端接口
→ 规则优先路由
→ 本地模型语义兜底
→ JSON Schema校验
→ 实体匹配
→ 后端权限校验
→ 现有业务服务适配层
→ 查询结果 / 写操作预览
→ 用户确认
→ 事务执行
→ 审计日志
```
模型只负责意图和参数；程序负责查数、算数和执行。禁止自由SQL。写操作必须预览和确认。权限从真实登录态读取。同名、歧义和缺参时停止。模型故障不影响传统系统。

## 五、前端
在管理后台和适合的内部管理端增加右下角“祥能AI业务助手”，打开右侧聊天抽屉；移动端用全屏或底部抽屉。提供五个快捷入口、示例问题、对话、查询表格、口径与更新时间、同名选择、补参表单、入离职预览卡、确认/修改/取消、操作结果、故障降级表单和健康状态入口。不得暴露原始提示词、数据库字段和完整工具参数。

## 六、后端接口
按项目风格实现等价接口：
- `POST /api/ai/chat`
- `POST /api/ai/actions/confirm`
- `GET /api/ai/actions/{actionId}`
- `GET /api/ai/health`
- `POST /api/ai/demo/reset`

`/chat`读取登录用户、运行规则路由、必要时调用模型、校验Schema、加载Skill、调用查询或预览工具。`/confirm`校验用户、token、过期时间、权限、状态、幂等键并通过正式业务服务事务提交。模型不得直接确认，确认必须来自用户点击。

## 七、规则与模型
优先使用 `config/intent-keywords.yaml` 和路由Skill。强规则唯一命中直接执行，复杂表达再调用模型。模型通过环境变量配置：`XIANGNENG_LLM_BASE_URL`、`XIANGNENG_LLM_MODEL`、`XIANGNENG_LLM_API_KEY`。temperature=0.1，10秒超时，单次仅提供命中Skill相关2至4个工具，支持预热、熔断和标准表单降级。

意图、工具参数和响应必须分别通过 `router/intent-schema.json`、各Skill `tool-schema.json` 和 `schemas/` 中Schema。Schema失败不得调用业务工具。

## 八、五项实现要求
1. 项目人员数据：月度入职、月度离职、当前在职、净增减，支持分公司/项目/时间/月度分组，返回表格、合计、口径、更新时间，与传统页面对账。
2. 人员信息：姓名、手机号、尾号、编号、状态、项目、入离职日期、供应商/推荐人和生命周期；同名返回脱敏候选。
3. 招聘进度：需求、完成、缺口、完成率、项目/岗位筛选和权限范围内排序。
4. 入职：单人、唯一人员、状态允许、日期/项目/岗位完整、权限通过、预览、确认、正式服务、事务、日志。
5. 离职：单人、唯一人员、当前在职、日期/原因完整、权限通过、原因标准化、预览、确认、正式服务、事务、日志。

不得支持批量入职、批量离职和删除人员。

## 九、权限
适配 `config/permissions.yaml` 和项目真实角色，建立映射。三层控制：前端显示、后端授权、数据范围过滤。禁止通过前端参数查询其他分公司或项目。

## 十、写操作安全
预览不写数据库，返回 action_id、action_token、过期时间、人员、before、after、影响范围和 confirmation_required=true。token与当前用户绑定，确认带唯一幂等键，执行前重新读取状态，使用事务，任何步骤失败整体回滚。审计日志记录操作人、角色、原始指令、Skill、参数、工具、前后数据、确认、action_id、幂等键、结果、错误、范围、模型和路由方式，敏感字段脱敏。

## 十一、稳定与演示
实现健康检查、模型预热、数据库和工具检查、超时、熔断、标准表单、独立演示数据、一键重置和传统页面入口。比赛断网时核心演示必须可运行。不得连接正式生产库做比赛写操作。

## 十二、测试
使用 `tests/` 和每个Skill的 `test-cases.jsonl` 建立自动化测试，覆盖意图、参数、负触发、同名、项目歧义、权限、状态、Schema失败、预览不写、确认写入、事务回滚、幂等、token过期、模型超时降级、无模型规则路由和与传统页面对账。每次修改运行 lint、类型检查、单元测试、集成测试、构建和关键页面访问测试。发现问题先修复，不得只在总结中列出。

## 十三、执行顺序
1. 审查与映射；
2. 三项只读MVP；
3. 入职和离职预览；
4. 确认、事务、幂等和日志；
5. 健康检查、降级和演示重置；
6. 完成验收清单。

## 十四、最终交付
输出审查结果、业务映射、文件清单、AI入口、五项Skill调用映射、模型环境变量、演示数据与重置、权限说明、事务幂等日志说明、测试命令和真实结果、演示步骤及对现有系统的影响。

现在开始：先审查仓库并更新 `docs/codex-mapping-guide.md`，输出审查结果前不要修改业务代码。
