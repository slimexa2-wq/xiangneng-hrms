# 祥能人员与招聘信息管理系统｜阶段交付报告

日期：2026-07-18

本报告按产品任务书的六个实施阶段记录真实产物。自动化夹具均以 `E2E` 或测试名称明确标识，不进入组织项目初始化数据。

## 第一阶段：基础工程

- 已完成：pnpm monorepo、Fastify API、React 管理端、Taro 小程序、统一共享类型、JWT 登录、RBAC、分公司/项目/供应商/本人数据范围、错误响应、上传存储接口和审计日志。
- 主要文件：`package.json`、`apps/api/src/app.ts`、`apps/api/src/plugins/auth.ts`、`apps/admin/src`、`apps/miniapp/src`、`packages/shared/src`。
- 数据库变化：建立用户、角色关联、分子公司、项目、人员、审计日志和业务主表；迁移位于 `prisma/migrations/20260718150000_init`。
- 验证：共享权限测试、API 鉴权/数据范围测试、三端类型检查和生产构建。
- 截图：`apps/admin/screenshots/admin-login.png`、`output/playwright/screenshots/dashboard-desktop-chromium.png`。
- 发现的问题：本机无 PostgreSQL/Docker，无法执行真实数据库和容器启动。
- 后续处理：以 Prisma schema/迁移一致性、Fastify inject 和 Compose 静态解析作为本机验证，并把真实环境复验列入最终边界。

## 第二阶段：真实组织项目初始化

- 已完成：完整读取四个工作表；过滤空白/说明/合计行；源哈希、7 个分子公司和 243 个项目对账；生成派生 JSON、异常清单、幂等 seed 与管理端 staged import。
- 主要文件：`packages/data-import/src`、`data/derived`、`prisma/seed.ts`、`apps/api/src/routes/imports.ts`、`docs/reports/组织项目初始化数据预处理报告.md`。
- 数据库变化：Branch 按名称、Project 按源项目 ID 幂等写入；保留 0 在职项目和全部空缺字段。
- 验证：源 Excel SHA-256、分公司汇总与明细交叉对账、243/243 接受、0 跳过；导入包测试通过。
- 截图：`apps/admin/screenshots/admin-people-import.png` 展示统一的“预览后提交”交互；组织导入使用同一页面模板。
- 发现的问题：3 组项目名称跨分公司重复；243 个项目的负责人、电话、期限、责任主体均缺失。
- 后续处理：使用源项目 ID 保持唯一、界面带分公司消歧；缺失字段保留“待维护”，不猜测。

## 第三阶段：人员主流程

- 已完成：身份证标准化查重、统一人员主档、运营报名、面试、入职、三类保险多选、离职、附件、备注、花名册筛选/批量操作/导入导出及状态历史。
- 主要文件：`apps/api/src/routes/people.ts`、`apps/api/src/services/registration.ts`、`apps/admin/src/pages/PeoplePage.tsx`、`apps/miniapp/src/pages/operator`。
- 数据库变化：Person、Application、PersonFile、StatusHistory；Application 保存自身面试/就业生命周期，历史岗位不会被人员当前状态覆盖。
- 验证：报名归并、分公司与项目写入范围、附件 IDOR、历史报名精确更新、桌面与移动 UI 流程。
- 截图：`output/playwright/screenshots/dashboard-*.png`、人员导入截图。
- 发现的问题：匿名请求不能安全覆盖既有档案。
- 后续处理：公开首报统一返回受理结果且不泄露档案存在性；既有人员仅幂等关联岗位、不修改 PII，进度查询要求身份绑定。

## 第四阶段：项目、供应商和政策

- 已完成：项目档案/实拍图/责任主体/期限、供应商级别与项目关系、两类政策、适用对象过滤、历史政策快照、供应商与资源专员权限隔离。
- 主要文件：`apps/api/src/routes/projects.ts`、`suppliers.ts`、`policies.ts`，以及对应管理端和小程序页面。
- 数据库变化：Supplier、SupplierProject、Policy、ProjectImage；人员与推荐记录保存政策快照。
- 验证：供应商只能向关联项目报人、Branch Manager 不能跨分公司盲写、政策按供应商级别/员工类型精确展示。
- 截图：`output/playwright/screenshots/projects-desktop-chromium.png`、`projects-mobile-chromium.png`、`resource-scope-*.png`。
- 发现的问题：管理端引用下拉最初仅取 200 条，无法选择最后 43 个真实项目。
- 后续处理：统一 `getAllPages` 遍历全部分页，并用 200+43 项测试防回归。

## 第五阶段：招聘主模块

- 已完成：招聘需求 CRUD、岗位绑定项目、需求/报名/到场/通过/入职/缺口口径、供应商报人、公开求职者首报、内部推荐、签名分享链接、推荐二维码接口、奖励状态与政策快照。
- 主要文件：`apps/api/src/routes/jobs.ts`、`applications.ts`、`referrals.ts`，管理端招聘需求/进度/奖励页，小程序岗位/报名/推荐页。
- 数据库变化：JobDemand、Application、ReferralRecord、ReferralReward、ReferralShare；同一人员可跨岗位/批次报名，报名记录自身保留生命周期。
- 验证：三类入口归并、重复岗位幂等、历史报名精确更新、公开接口不泄露人员存在性、推荐 token 过期/岗位绑定、项目实拍图公开范围。
- 截图：管理端招聘需求包含在 Playwright 双视口流程；小程序源码构建通过，真机截图受微信开发者工具缺失限制。
- 发现的问题：二维码 scene 只包含签名 token，需安全解析岗位；新需求通知不能依赖未配置模板伪发送。
- 后续处理：增加公开 token 解析接口；新需求向关联项目活跃供应商写幂等通知，未配置时记录 `SKIPPED_NOT_CONFIGURED`。

## 第六阶段：工资条和微信能力

- 已完成：工资条模板、multipart 预览、人员匹配、异常清单、批次提交、发布/撤回、员工本人读取；微信 `code` 登录/绑定、通知队列/重试、模板配置检测、推荐二维码和小程序路径。
- 主要文件：`apps/api/src/routes/salary.ts`、`notifications.ts`、`services/salary-workbook.ts`，管理端工资条页，小程序工资条/个人页，`docs/微信真实配置清单.md`。
- 数据库变化：SalaryImportBatch、SalarySlip、Notification；工资条按人员和月份约束、仅本人可读。
- 验证：工资条预览警告、批次状态、发布/撤回、本人/他人权限；微信未配置分支不伪报成功。
- 截图：工资条与配置页面包含在可运行管理端；未生成虚假微信消息或二维码截图。
- 发现的问题：真实 AppID、Secret、公众号模板、合法域名和绑定 OpenID 未提供。
- 后续处理：按配置清单在测试号/正式号完成真实消息、二维码和跳转复验；普通字段修改不进入通知队列。
