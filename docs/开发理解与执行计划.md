## 准备复用的技术栈

本项目无既有代码，采用单体优先的 pnpm monorepo：

- `apps/admin`：React + TypeScript + Vite + Ant Design；
- `apps/miniapp`：Taro + React + TypeScript，统一承载运营、供应商、求职者和员工角色入口；
- `apps/api`：Node.js + TypeScript + Fastify，按业务模块组织但单体部署；
- `packages/shared`：共享枚举、Zod 校验、API 契约和权限定义；
- 数据库：PostgreSQL + Prisma；
- Excel：ExcelJS，执行“预览校验—确认写入—结果清单”；
- 文件：本地开发存储，通过存储接口预留对象存储替换点；
- 权限：RBAC + 分子公司/项目/本人/供应商数据范围；
- 测试：Vitest + Fastify 注入测试 + Playwright；
- 部署：Docker Compose，保持单体 API、管理端和 PostgreSQL 的简单组合。

## 风险与验证方法

- **同名项目与产品全局唯一规则冲突**：保留源项目 ID 和分子公司归属，以复合业务键防止同分子公司重复，并在 UI/导出中带分子公司消歧；导入报告固定列出 3 组冲突。
- **参考图缺失**：先按产品说明完成功能闭环和响应式结构；截图交付会注明当前视觉基线，图片到齐后再做差异回归。
- **无 Docker/PostgreSQL**：使用 Prisma 校验/生成和迁移 SQL检查，核心业务与 API 使用隔离测试；本机直接启动前后端并用 Playwright 验证。Docker 实启不伪报完成。
- **权限越权风险**：为总部、分子公司、项目、供应商、员工、求职者和管理员分别编写允许/拒绝测试，工资条和敏感字段单独验证。
- **统计口径风险**：所有卡片和图表只查询业务明细；每项统计测试同时核对下钻 ID 集合和数量。
- **重复人员风险**：身份证号标准化后唯一约束，报名入口统一调用“查找或创建档案”服务并写状态日志。
