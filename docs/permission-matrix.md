# 祥能 HRMS 权限矩阵

## 1. 计算规则

1. 用户可以拥有多个有效角色。
2. 后端从登录会话加载有效角色与范围绑定，不接受客户端自行声明范围。
3. 每个有效角色分配与其功能权限、数据范围、来源和有效期组成独立授权包。
4. 服务端先筛选拥有目标权限的授权包，再合并这些授权包允许的数据谓词；禁止把角色 A 的权限与角色 B 的范围交叉组合。
5. 调动生效时结束旧组织任职和旧组织范围授权。
6. 账号停用或内部员工离职后立即撤销会话和全部业务权限。
7. 所有授权、撤权、密码重置、停用、删除、调动和导出记录审计。

## 2. 数据范围

| 范围 | 后端过滤依据 |
|---|---|
| 仅本人 | 当前用户关联的内部员工或派遣人员 ID |
| 本部门 | 当前有效任职的部门节点 |
| 本中心 | 当前中心节点及直接下属业务部门 |
| 项目地域分公司 | 仅用于项目、招聘需求、派遣外包等经营地域数据，不用于内部花名册组织 |
| 指定项目 | `DataScopeBinding` 中的项目 ID |
| 指定供应商 | `DataScopeBinding` 中的供应商 ID |
| 集团全部 | 独立高权限授权，不由前端参数触发 |

### 2.1 内部组织与法律主体边界

- 内部组织固定为“集团 → 中心 → 业务部门”。
- 花名册中的宜宾分公司、绵阳分公司、双流分公司、保安公司等均按业务部门管理。
- 合同主体是员工签订劳动合同的法律公司，仅保存在员工及任职记录上；同一业务部门可以存在多个合同主体，不作为内部数据范围。
- `BRANCH` 数据范围继续服务项目和外派业务，但内部员工、任职历史、组织单元和内部岗位绑定均不再使用该字段。

## 4. 字段权限

- 内部授权页面与 AI 查询按权限返回完整电话、身份证、银行卡和合同字段，不做统一脱敏。
- 工资和银行卡仅本人、工资管理授权和指定财务角色可访问。
- 身份证和合同仅人员档案授权角色可访问。
- 报销附件仅报销人本人、当前处理节点角色和授权审计角色可访问。
- 公开演示数据为合成数据，即使完整显示也不得与真实个人对应。

## 5. AI 权限

- AI查询与传统页面使用同一数据范围服务。
- AI入职和离职只能操作当前用户拥有正式写权限的单个人员。
- 模型输出不能提升权限，不能指定其他业务部门、项目地域、项目或供应商绕过范围。
- 入离职确认 token 绑定当前用户、操作、人员、预览版本和过期时间。

## 6. 岗位、职级与账号联动

### 6.1 岗位绑定职责角色

- `PositionRoleBinding` 将岗位绑定到系统角色及默认数据范围。
- 岗位授权生成的 `UserRoleAssignment.source` 固定为 `POSITION`。
- 员工入职、调岗、账号绑定或岗位配置变化时，系统只替换 `POSITION` 来源授权。
- `MANUAL` 与 `TEMPORARY` 来源授权不随岗位变更删除，避免误伤兼岗和临时代理授权。
- 清空岗位绑定时，会撤销该岗位全部在职、已绑定账号员工的岗位授权，并刷新账号令牌。

### 6.2 职级控制审批额度

- `JobGradeApprovalPolicy.maxReimbursementApprovalCents` 控制负责人审核报销时的付款金额上限。
- 未配置职级策略时保持兼容，不额外限制审批金额。
- 职级只控制审批额度，不直接授予财务、出纳或集团数据权限。

### 6.3 账号绑定与权限刷新

- 一个系统账号最多绑定一名内部员工，一名内部员工最多绑定一个系统账号。
- 绑定或换绑时，旧账号的岗位授权被撤销，新账号按员工当前岗位、业务部门和所属中心重新生成授权。
- 解绑时撤销岗位来源授权，但不删除员工档案。
- 绑定、换绑、解绑均写入内部员工变更记录和审计日志。

### 6.4 防止权限升级

- 非超级管理员、系统管理员不得通过岗位配置授予 `GROUP` 数据范围。
- 非超级管理员、系统管理员不得通过岗位配置授予集团负责人或总部管理者角色。
- 前端会隐藏不可授予选项，服务端仍执行最终校验，不能依赖页面隐藏代替权限控制。

## 7. 报销权限与岗位建议

| 岗位职责 | 推荐角色 | 关键权限 | 默认数据范围 |
|---|---|---|---|
| 普通内部员工 | 普通内部员工 | `reimbursement:self` | 本人 |
| 部门报销制单人 | 部门报销制单人 | `reimbursement:manage` | 本部门 |
| 部门负责人 | 部门负责人 | `reimbursement:approve` | 本部门或本中心 |
| 财务审核岗 | 财务审核 | `reimbursement:finance-review`、`reimbursement:export` | 本部门、本中心或集团 |
| 出纳岗 | 出纳 | `reimbursement:pay` | 本部门、本中心或集团 |

报销权限按“角色 + 权限 + 数据范围”授权包判断。某个角色拥有报销权限时，只能使用该角色自身绑定的数据范围，不能与另一个角色的数据范围自由组合。
