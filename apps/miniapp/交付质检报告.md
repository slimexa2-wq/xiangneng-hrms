## 范围核对

- 单一 Taro 小程序按登录角色提供内部运营、供应商、求职者、内部员工四类工作台。
- 已注册 20 个页面，覆盖人员报名、面试、入职、离职、人员查询/详情/附件备注、招聘需求/详情/报人、供应商人员/数据/政策、求职者报名进度、内部推荐/奖励、工资条和我的信息。
- 所有页面只调用统一 API；源码未写入人员、项目、岗位或工资条演示数据。
- 供应商与推荐人由服务端根据当前登录身份绑定；小程序不提供自由选择入口。
- 页面不包含员工头像。

## 关键契约核对

- 三类报名与运营报名统一使用人员查重服务，返回字段按 \`{ person, application, deduplicated }\` 定义；页面不因重复身份证号创建第二套字段。
- 微信登录只调用 \`Taro.login\` 获取临时 code，再交 \`/wechat/auth/login\`；小程序不接触 AppSecret。
- 岗位列表展示脱敏负责人电话，岗位详情从后端获取可拨打号码，并提供一键拨号和复制。
- 人员附件上传走 \`/people/:id/files\`，查看时携带 Bearer Token 下载 \`/people/:id/files/:fileId\`。
- 项目实拍图通过受保护文件接口下载为微信临时文件后展示，不把受保护地址直接裸露给 Image 组件。
- 求职者报名、供应商报人和员工推荐分别使用 \`SELF\`、\`SUPPLIER\`、\`REFERRAL\` 来源；供应商和推荐人由后端覆盖绑定。

## 已知边界

- 本机标准路径未发现微信开发者工具，无法在本机生成可信的小程序模拟器或真机截图；已完成编译产物验证，但不能声称已完成微信端视觉/控制台实机验证。
- 当前没有真实小程序 AppID/AppSecret、合法域名、公众号身份绑定与模板 ID。界面明确显示缺口；微信登录与通知不能视为真实可用。
- \`project.config.json\` 使用 \`touristappid\`，仅用于构建和开发者工具导入。上线前必须替换为真实 AppID，并将 API 切换为备案 HTTPS 合法域名。
- 订阅消息必须由用户点击触发后申请；当前模板 ID 缺失，因此未发起订阅，也未伪报通知成功。

**有条件交付。** 小程序源码、类型检查、单元测试和 weapp 构建均通过；真实微信登录、订阅/公众号通知、模拟器与真机页面截图必须在微信配置和开发者工具到位后补验。
